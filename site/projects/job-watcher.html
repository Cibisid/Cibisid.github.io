job-watcher

A scheduled pipeline that monitors about 430 employer career sites, filters out noise and ranks new postings by fit.

The problem

Relevant roles are fragmented and short-lived.

Openings are published across hundreds of separate employer career sites. Large job boards index them late, duplicate them, and mix in staffing agencies advertising the same role repeatedly, so tracking them manually is slow and incomplete.

job-watcher queries employers' applicant-tracking systems directly, on a schedule, and surfaces only the postings that meet defined criteria.

How it works

A serverless pipeline built entirely on GitHub.

1. Scheduled runGitHub Actions is set to start a scan every 3 hours. In practice GitHub runs about 3 a day, because it delays or skips scheduled jobs when busy. A weekly job looks for new company boards.
→
2. Read the career boardsReads about 430 boards in parallel straight from the hiring systems companies use: Greenhouse, Lever, Ashby, Workday and Amazon's own site.
→
3. Screen and scoreDrops staffing agencies, roles that won't sponsor and poor matches, then scores the rest for fit.
→
4. PublishUpdates a dashboard of open roles, newest first, and opens a GitHub issue for new ones so an email arrives.

Key decisions

Designed for zero infrastructure cost.

Go to the source

Only company career boards, never aggregators. That removes most of the noise before any filtering happens: no reposts and far fewer staffing-agency listings.

Trade-off: each hiring system has its own format, so there's a reader for each one.

GitHub is the whole platform

Actions is the scheduler, JSON files in the repo are the database, the README is the dashboard, and issues are the email alerts. It costs nothing and there's nothing to keep running.

Trade-off: history lives in commits, which suits this scale but wouldn't suit millions of rows.

Standard library only

No third-party packages, so nothing breaks on a scheduled runner when a dependency changes.

Trade-off: a little more code for HTTP and parsing.

Track the health of every board

Each run records whether every board answered. A check command tests them all, so a company that changes its careers site is noticed instead of silently dropping out.

Trade-off: an extra status file to maintain.

Results

Scale.

  • Hundreds of matching open roles at well over a hundred companies on the live dashboard at any time, newest first.
  • Connected to a scoring tool that rates shortlisted roles in more depth and writes the scores back to the dashboard.

Roadmap

Planned improvements.

  • Run on a reliable scheduler. GitHub skips some scheduled runs, so only about 3 of the 8 planned scans a day happen.
  • Add automated tests for each board reader and the screening rules.
  • Publish a public version that anyone can point at their own list of companies.
